# Тестовое задание frontend-разработчик “Цифровое Телевидение”

Интерфейс для работы с материалами (список, просмотр, создание с WYSIWYG-редактором) телеканала «Моя Планета».

---

## 🛠 Стек технологий

* **Nuxt 3** (v3.16+) + **Vue 3** (Composition API, `<script setup>`);
* **TypeScript** для строгой типизации моделей и ответов API;
* **Less** — препроцессор стилей;
* **CSS-переменные (дизайн-токены)**: цвета, шрифты, отступы, тени, радиусы вынесены в `assets/styles/variables.less` и используются во всех компонентах;
* **Шрифты**: локальное подключение `Futura PT` (заголовки) и `Source Sans 3` (основной текст) через `@font-face` в `assets/styles/fonts.less`;
* **State Management**: **Pinia** (`@pinia/nuxt`) для централизованного хранения состояния и кэширования списка материалов;
* **WYSIWYG-редактор**: **TipTap** (`@tiptap/vue-3`, `@tiptap/starter-kit`, `@tiptap/extension-placeholder`) с экспортом в `HTML` и `JSON`;
* **Адаптивность**: полноценная адаптивная верстка (десктоп, планшет, мобильные устройства).

## 🚀 Установка и запуск проекта

### Требования
* Node.js v18+ или v20+
* Менеджер пакетов `npm`

### 1. Клонирование репозитория
```bash
git clone <url-репозитория>
cd dtv-test
```

### 2. Установка зависимостей
```bash
npm install --legacy-peer-deps
```
*(Флаг `--legacy-peer-deps` рекомендуется для чистого разрешения зависимостей в некоторых окружениях npm 10)*

### 3. Переменные окружения (опционально)
По умолчанию используется персональный псевдоним `groshev`. При необходимости изменить псевдоним или базовый URL API, создайте файл `.env`:
```env
NUXT_PUBLIC_API_ALIAS=groshev
NUXT_PUBLIC_API_BASE_URL=https://naukatv.ru/api/test/materials
```

### 4. Запуск в режиме разработки
```bash
npm run dev
```
Приложение будет доступно по адресу: [http://localhost:3000](http://localhost:3000)

### 5. Сборка для продакшена
```bash
npm run build
npm run preview
```

## 📋 Ответы на обязательные вопросы задания

### 1. Какой из трёх вариантов получения данных для детальной страницы вы выбрали и почему?

**Выбранный вариант**: **Хранилище состояния (Pinia store)** с гибридным фоллбэком на загрузку списка при прямом переходе.

**Обоснование:**
1. **Производительность и UX (кэширование)**: При переходе пользователя из списка материалов на детальную страницу данные уже присутствуют в сторе. Это обеспечивает мгновенное открытие страницы без лишнего сетевого запроса и задержек для пользователя.
2. **Поддержка прямого перехода (Deep Linking & Refresh)**: Если пользователь переходит по прямой ссылке на детальную страницу (`/materials/[id]`) или обновляет её в браузере (F5), стор определяет отсутствие данных и автоматически запрашивает актуальный список материалов через API, находя нужный элемент по `id`.
3. **Единый источник истины (Single Source of Truth)**: После создания нового материала на странице `/materials/create`, созданный объект с присвоенным `id` сразу помещается в стор `materialsStore`. При редиректе на детальную страницу данные отображаются мгновенно.
4. **Недостатки альтернатив**:
   * *Только пропсы*: не работают при прямом переходе по URL или обновлении страницы.
   * *Только поиск по роуту в компоненте*: дублирует логику запросов между страницами и не позволяет переиспользовать уже загруженное состояние.

### 2. Как устроена проверка длины полей `title` и `short_description`?

Проверка реализована **на двух уровнях**: на клиенте (UI/UX) и на сервере (валидация перед отправкой запроса к внешнему API).

#### Клиентский уровень:
1. **Интерактивные счётчики символов**:
   * Для поля `title` отображается счётчик `form.title.length / 80`.
   * Для поля `short_description` отображается счётчик `form.short_description.length / 255`.
   * При приближении к лимиту счётчик меняет цвет, сигнализируя пользователю.
2. **Атрибут `maxlength`**: На уровне HTML-разметки инпутам заданы атрибуты `maxlength="80"` и `maxlength="255"`, что физически предотвращает ввод лишних символов с клавиатуры.
3. **Реактивная валидация (`@input`)**: Функции `validateTitle` и `validateShortDesc` проверяют длину введённого значения и формируют понятные сообщения об ошибках.
4. **Блокировка кнопки отправки**: Вычисляемое свойство `isFormValid` блокирует кнопку «Сохранить материал», пока `title` пуст или длина полей превышает установленные лимиты.

#### Серверный уровень (Nitro server route `server/api/materials/save.post.ts`):
Перед отправкой данных во внешний API сервер Nuxt выполняет проверку:
```typescript
if (!body.title || typeof body.title !== 'string') {
  throw createError({ statusCode: 400, statusMessage: 'Поле title обязательно' })
}
if (body.title.length > 80) {
  throw createError({ statusCode: 400, statusMessage: 'Длина поля title не должна превышать 80 символов' })
}
if (body.short_description && body.short_description.length > 255) {
  throw createError({ statusCode: 400, statusMessage: 'Длина поля short_description не должна превышать 255 символов' })
}
```

### 3. Как решили вопрос с CORS?

**Решение**: **Серверные обработчики Nuxt (Nitro Server Routes / API Proxy)**.

**Механизм работы:**
1. Браузерные ограничения CORS действуют исключительно при кросс-доменных запросах из браузера (например, с `http://localhost:3000` на `https://naukatv.ru`).
2. В приложении созданы серверные маршруты:
   * `server/api/materials/index.get.ts` — проксирует GET-запрос к `https://naukatv.ru/api/test/materials/{alias}`
   * `server/api/materials/save.post.ts` — проксирует POST-запрос к `https://naukatv.ru/api/test/materials/{alias}/save`
3. Клиентская часть (браузер) обращается к эндпоинтам своего же домена (`/api/materials`), что полностью устраняет CORS-блокировки браузера.
4. Сам Nuxt-сервер (на базе Node.js/Nitro) выполняет запросы к внешнему API на уровне сервера без каких-либо CORS-ограничений.
5. Дополнительно в `nuxt.config.ts` настроено правило `nitro.routeRules` (`/api-proxy/**`), обеспечивающее возможность прямого проксирования при необходимости.

## 🎨 Реализация страниц

1. **Список материалов (`/`)**:
   * Сортировка по дате (новые публикации выше).
   * Скелетонная загрузка при ожидании ответа.
   * Экран пустого состояния (Empty State) с кнопкой быстрого перехода к созданию, если список пока пуст.
   * Адаптивная сетка карточек: от 4 колонок на больших экранах до 1 колонки на мобильных устройствах.
2. **Детальная страница (`/materials/[id]`)**:
   * Кнопка «Назад» для возврата к общему списку.
   * Отображение даты публикации, заголовка, лид-абзаца и отрендеренного контента WYSIWYG-редактора с правильной типографикой заголовков (h1-h3) и цитат.
   * Обработка состояния «Материал не найден».
3. **Создание материала (`/materials/create`)**:
   * Форма с полями: заголовок, краткое описание, дата и время (по умолчанию текущие с возможностью изменения через нативный пикер), WYSIWYG-редактор TipTap.
   * Передача на сервер обоих форматов редактора (`description_html` и `description_json`).
   * Индикатор сохранения (лоадер на кнопке).
   * Автоматический переход на детальную страницу созданного материала после получения ответа от сервера.
